Core Architectural Design: EDMMA with Apache Kafka

Why choose an Event-Driven Modular Monolith (EDMMA)?

  • Microservices Pitfall: Introduces massive operational complexity, costly network overhead, and complex cross-boundary data tracking.
  • Traditional Monolith Drawback: Suffers severe performance bottlenecks and blocking when handling multi-tenant heavy AI inferencing synchronously.
  • The Hybrid Choice: Keeps the domain core secure and clean as a C# .NET Core, while offloading compute-heavy tasks asynchronously via Apache Kafka to distributed Python worker nodes.

Technical Engineering Challenges & Resolution Pathways

Challenge: Aggregating diverse property datasets across fragmented local markets

Solution: Built robust web scraping systems and aggregated data from local sources, standardizing schemas and regional values inside EDMMA before training models.

Challenge: Real-time data ingestion from dynamic, constantly shifting listing platforms

Solution: Implemented a streaming pipeline within EDMMA that captures data on the fly, dispatching events through Kafka to synchronize storage and execution layers seamlessly.

Challenge: Addressing data noise, price anomalies, and missing metadata fields

Solution: Enforced rigid price normalization techniques, cleaned outliers, and used advanced imputation methods to make features predictable and easy to analyze.

Challenge: Labeling highly sensitive identification data at scale safely

Solution: Adopted a Human-in-the-Loop approach to review sensitive files, anonymizing personal identifiable information (PII) before model training loops.

Challenge: Processing deep learning workflows without blocking the transactional backend core

Solution: Isolated AI workloads into independent asynchronous services within EDMMA, managing heavy requests via Kafka to protect baseline system response speeds.

Challenge: Uncovering hidden forgery across uploaded imagery and legal paperwork

Solution: Layered FAISS vector matching for visual verification, OCR for layout text analysis, and DeepFace biometric matching in concurrent validation loops.

Challenge: Scalability barriers when syncing real-time user chats and high-frequency checkouts

Solution: Separated conversational tasks into an independent Flask system powered by Socket.IO, while wrapping financial pipelines in PCI-DSS protocols and fraud detection checks.

Engineering Lessons Learned

01

Prioritize Architecture Before Writing Code

Adopting the EDMMA structural design early saved us from extensive code refactoring, providing clean interfaces to expand our AI microservices easily.

02

Isolate Conversational Workloads for Better Performance

Separating Flask to handle real-time messaging outside the main .NET Core application eliminated thread pool starvation and allowed both services to scale independently.

03

Treat Security as a Core Feature, Not an Afterthought

Building 2FA, biometric checks, and role-based access from day one was critical; integrating these mechanisms later would have added massive complexity to our stable schemas.

04

Cross-Functional Teams Accelerate Software Delivery

Splitting engineering goals concurrently across Backend, Frontend, AI, and DevOps specialists maximized output and cut down our time-to-market metrics significantly.
